# Video Harvester

Распределённое обнаружение и загрузка публичных незашифрованных видео Kinescope. Координатор выдаёт небольшие блоки ID, агенты проверяют страницы, сохраняют реальные медиафайлы и передают прогресс в общую базу.

Рабочий источник — **Kinescope**, не mock. Тестовый HTTP-сервис включается отдельно только для автоматических испытаний. DRM, страницы с авторизацией, ответы 401/403 и зашифрованные HLS не обходятся. Поддерживаются публичные MP4 и конечные HLS без смены временной шкалы. Если формат не поддержан, система сохраняет явную ошибку, а не фиктивный файл.

## Требования

Python 3.11+, FFmpeg с ffprobe, OpenSSL. Рабочие серверы — Linux или macOS. SQLite хранится на локальном диске координатора; сетевой файловый ресурс для БД не используется. Агенты работают без root. Для удалённых узлов нужен OpenSSH.

## Первый запуск

Все команды выполняются из корня проекта. В Windows используйте Linux/WSL: файловые блокировки реализованы через `fcntl`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/setup_local.py
python -m agent.agent --check
```

`setup_local.py` создаёт `config.yaml`, учебный TLS-сертификат, отдельные токены агентов и случайные пароли. Существующие секреты не перезаписываются. Пароль пользователя `admin` находится в `.env.coordinator`, переменная `BOOTSTRAP_ADMIN_PASSWORD`. Файлы `.env.*`, `.secrets/`, БД и медиа исключены из Git.

Запустите координатор:

```bash
source .venv/bin/activate
uvicorn coordinator.app:app --host 127.0.0.1 --port 8000 \
  --env-file .env.coordinator \
  --ssl-keyfile certs/key.pem --ssl-certfile certs/cert.pem
```

Откройте <https://localhost:8000>. Браузер попросит принять самоподписанный учебный сертификат; агенты проверяют его через `CA_CERT`, отключать проверку TLS не нужно.

Создайте задание с диапазоном `[200810246,200810246]`. Это ровно одно видео из примера преподавателя. Нажмите «Старт». Посмотрите ID задания в адресе `/jobs/1` и подставьте его вместо `1` ниже.

В трёх отдельных терминалах:

```bash
source .venv/bin/activate
python -m agent.agent worker-01 1 --env-file .env.worker-01
```

```bash
source .venv/bin/activate
python -m agent.agent worker-02 1 --env-file .env.worker-02
```

```bash
source .venv/bin/activate
python -m agent.agent worker-03 1 --env-file .env.worker-03
```

Для одного ID работает один агент; это ожидаемо. Несколько серверов нужны для диапазона с несколькими блоками. Не увеличивайте диапазон реального ресурса ради нагрузочного теста: для нагрузки предусмотрен локальный тестовый стенд.

Агент остаётся подключённым после паузы, остановки и завершения задания, поэтому «Продолжить» и «Повторить ошибки» не требуют нового ручного запуска. Параметр `--once` завершает процесс после конечного состояния — он используется в проверочных скриптах.

Готовый файл: `data/worker-XX/200/200810246/video.mp4`; рядом `metadata.json`. В интерфейсе смотрите статус, активные операции, журнал и данные серверов.

## Проверки

```bash
python -m pytest -q
python scripts/system_check.py --mode failure
python scripts/system_check.py --mode load --workers 10
python scripts/live_check.py
```

Первые три команды используют локальные данные. Последняя загружает ровно одно публичное видео преподавателя и требует интернета. `system_check.py` запускает и останавливает собственные процессы, использует временную БД и сохраняет отчёты в `docs/`. Сначала выполните `setup_local.py`: процессным проверкам нужны сертификаты.

## Обновление существующей версии

1. Сделайте резервную копию SQLite через `sqlite3.Connection.backup`, остановите старые агенты и координатор.
2. Обновите исходники и зависимости, настройте персональные токены.
3. Запустите координатор: миграция схемы 2 выполняется идемпотентно и сохраняет существующие результаты.
4. Запустите агенты версии 2. Старые агенты 1.x отклоняются: у них нет токена конкретной аренды, поэтому принимать их результаты небезопасно.

Старые задания сохраняют источник `mock`, потому что именно с ним работала версия 1. Для реального ресурса создайте новое задание Kinescope. Завершённые записи старой БД не превращаются в реальные видео автоматически.

Подготовку удалённых серверов, смену токенов, схемы и разбор каждого компонента см. в [руководстве](docs/guide.md).
