# Проверка новой версии

Все приведённые ниже результаты относятся к локальному стенду macOS и конкретной версии исходников. Тестовые процессы не заменяют проверку сети между тремя реальными VPS.

## Автоматические проверки

Запуск: `python -m pytest -q`.

Проверяются исходные сценарии и регрессии: чужое имя/токен, устаревшая попытка аренды, сохранение вне блока, идемпотентность, порядок результатов, повтор ошибок, подключение нового сервера, доставка параметров, общий limiter, ленивые диапазоны, точный предел ID, остановка, путь с traversal, ошибочный диапазон, формы журналов, Range, повреждение частичного файла, HTTP-дата Retry-After, разбор реальной страницы, HLS и повтор 500 во время скачивания.

Финальное число тестов и результат фиксируются в `test-summary.txt` после последнего прогона.

## Отказ процессов

Команда: `python scripts/system_check.py --mode failure`.

Реальные отдельные процессы, HTTPS с проверкой сертификата. Три агента, 42 ID. Один агент принудительно завершён, координатор принудительно завершён и запущен заново. Подтверждённые результаты до перезапуска сравнены с итоговыми.

Измеренный результат первоначального успешного прогона новой версии: 42/42 ID, 5 файлов, 0 ошибок, 1 возврат истёкшей аренды, 6 подтверждённых ID до перезапуска, 12.488 секунды. Актуальный машинный отчёт — `failure-check.json`.

## Нагрузка

Команда: `python scripts/system_check.py --mode load --workers 10`.

Десять отдельных процессов агентов по 12 потоков, координатор, HTTPS и отдельный управляемый источник. 240 ID, ответы источника задержаны на 3 секунды и возвращают 404. Измеряется число одновременно выполняющихся HTTP-обработчиков источника, а не только настройка пула.

Измеренный пик — **120 одновременных запросов**. 240/240 ID завершены без ошибок за 7.967 секунды. Отчёт — `load-check.json`.

Этот результат доказывает требуемую параллельность проверки в тестовой среде. Он не измеряет производительность скачивания 120 больших реальных видео и не разрешает переносить такую нагрузку на внешний сайт.

## Реальный источник

Команда: `python scripts/live_check.py`.

Ровно один ID: 200810246. Используются рабочий Kinescope-адаптер, HTTP Range, HLS, FFmpeg, проверка итогового контейнера, отдельные процессы и HTTPS. Успешный прогон с докачкой завершился за 420.68 секунды. Получен настоящий MP4 размером 260 333 424 байта, длительностью 5428.003991 секунды, с H.264 640×360 и AAC. Это время последнего успешного прогона, а не сумма всех предшествующих попыток и сетевых обрывов. Сводка — `live-download-check.json`.

После последних исправлений повторный запуск переиспользовал проверенный готовый файл, завершился за 6.22 секунды и подтвердил `completed`, HTTP 200, `error_code: null`. Его полный результат и ffprobe — `live-check.json`. Значение среднего объёма файлов в секунду в таком повторе не является скоростью сети: текущий сетевой счётчик равен нулю.

## Практические границы

- SQLite находится на одном хосте. Автоматический HA и PostgreSQL в этой версии не заявлены.
- Схема 2 мигрирует данные версии 1, но старые агенты необходимо обновить: запросы без токена аренды отвергаются.
- Поддерживается публичный MP4 и конечный незашифрованный HLS. DRM, авторизация, live и discontinuity дают явную причину, не фиктивный успех.
- Команда остановки асинхронна: отмена приходит с heartbeat; блокирующее чтение ограничено HTTP timeout.
- Подтверждённые результаты идемпотентны; неподтверждённые локальные файлы на потерянном узле могут остаться.
- Файлы не реплицируются между серверами. Повреждение уже подтверждённого файла после успешной загрузки требует отдельной проверки хранилища и повторного задания.
- Для очень длительной эксплуатации нужны политика хранения метрик и журналов, резервные копии и мониторинг самого координатора.
- Реальные SSH/VPS не предоставлялись; удалённые команды подготовлены и описаны, но результат на конкретном внешнем сервере не заявляется.

## Проверка интерфейса и руководства

В отдельном headless Chrome проверены вход, создание, старт, пауза, продолжение и остановка; пустые фильтры журналов; ширина 390 пикселей без выхода страницы за экран. Ошибок JavaScript не обнаружено. Результат — `browser-check.json`. У автономного руководства проверены 22 раздела, 13 блоков кода, загрузка всех изображений и мобильная вёрстка.
