# Изменения по результатам проверки

Исходная версия: `b2e262c8f23df012f2c0ec696c0bd5793ac3fe17`. Новая версия протокола: 2.0. Это изменение существующей архитектуры, а не замена задачи другой демонстрацией.

| Было | Стало | Зачем и где |
|---|---|---|
| HTTP 200 всегда разбирался как JSON | Адаптер Kinescope извлекает `playerOptions`, публичный MP4/HLS; JSON вынесен в тестовый адаптер | Реальная ссылка обрабатывается в `agent/sources.py` |
| Mock являлся единственным источником | По умолчанию Kinescope; `allow_test_source: false` | Рабочий режим не генерирует фиктивные файлы |
| Heartbeat отправлялся между пачками | Отдельный поток и отдельный HTTP-клиент | Медиа-загрузка не блокирует управление, `Agent.heartbeat_loop` |
| Пустой progress мог изменить checkpoint | Heartbeat только продлевает аренду | Прогресс двигается только по сохранённым конечным результатам |
| Старый агент мог записать результат | Проверка имени, `job_id`, `chunk_id`, `lease_token`, срока и состояния до записи | `service.owned` и общая транзакция |
| `next_id` мог уменьшиться | `advance` вычисляет непрерывный подтверждённый префикс | Устранён откат из-за порядка доставки |
| `threading.Lock` действовал в одном процессе | `BEGIN IMMEDIATE` сериализует выдачу и запись через SQLite | Несколько API-процессов не получают один блок одновременно |
| Весь конечный диапазон материализовался сразу | Блоки создаются по требованию из `next_range_start` | Большой диапазон не создаёт миллионы строк при нажатии «Создать» |
| Новый worker не попадал в старое задание | Автоматическое назначение для заданий «все серверы», явное назначение для выбранных | `assign_workers` и PUT назначения |
| Стартовые параметры задания игнорировались | В lease приходят timeout, retries, threads, connections, storage и reserve | Агент исполняет настройки координатора |
| Общая квота делилась на число агентов и устаревала | Каждому внешнему HTTP-запросу нужен общий `permit` | Смена числа агентов не увеличивает квоту |
| Rate limit относился преимущественно к страницам | Учитываются страницы, редиректы, плейлисты и куски медиа | Общее ограничение плюс раздельные лимиты check/download и worker |
| Повторы охватывали только проверку страницы | Повторяется весь цикл до подтверждённого файла; целые куски переиспользуются | Ошибки скачивания больше не теряются |
| Retry-After понимал только секунды | Поддерживается также HTTP-дата | `agent/http.py` |
| «Повторить ошибки» оставляло job завершённым | Явная операция переводит ошибочные элементы в pending и job в running | Подтверждённые хорошие элементы пропускаются |
| Остановка ждала всю пачку | Команда отзывает аренду, heartbeat выставляет отмену, поток проверяет её при чтении | Остановка ограничена интервалом управления и сетевым тайм-аутом |
| Пауза продолжала весь блок | Завершаются только уже начатые ID, остаток блока возвращается | Не начинают новые операции после получения паузы |
| Готовый `.part` запрашивал невозможный Range | Проверяются размер и SHA-256 checkpoint, файл продвигается без запроса | Исправлен случай сбоя непосредственно перед переименованием |
| Частичный файл мог быть повреждён | Сохраняется digest checkpoint, повреждённая часть перезапускается | `fetch_file` |
| Нет HLS | Незашифрованный VOD, аудио/видео, Range, группировка соседних диапазонов, локальный remux | FFmpeg не обращается к сети и не обходит общий лимит |
| Удалённый путь с `..` принимался | Traversal отвергается до проверки принадлежности каталогу | `common/paths.py` |
| Один токен давал право представляться любым worker | Отдельные токены по имени; поддерживается временное перекрытие при ротации | `security.check_agent_token` |
| Регистрация стирала host и включала отключённого worker | Существующие административные настройки сохраняются | Регистрация меняет версию, доступность и heartbeat |
| SSH запускал системный Python | Запускается `.venv/bin/python`, секреты читаются из `.env.agent` | Отсутствие окружения выявляет probe |
| Метрики снимались после выполнения пачки | Независимые snapshots активных ID, байтов, соединений, swap, I/O и задержек | Число соединений измеряется приложением, не равно константе 0 |
| Страница задания не обновлялась | Live-области обновляются каждые 3 секунды без сброса форм | `base.html` |
| Веб-форма была неполной | Тайм-ауты, повторы, глобальные потоки, соединения, остановка, серверы и квоты | Dashboard, назначение worker, серверные формы |
| Не было отдельных worker/metrics endpoints | Добавлены детали worker, история метрик и аудит | REST API версии 2 |
| Миграция не применялась; индексы из SQL отсутствовали | Идемпотентное обновление и индексы при запуске | `coordinator/migrate.py` |
| Тест «перезапуска» повторно создавал таблицы | Реальный процесс убивается, поднимается снова; проверяются подтверждённые ID | `scripts/system_check.py --mode failure` |
| Нагрузочный скрипт обходил агентов и координатор | 10 агентов и полный API-протокол; измеряется фактический пик запросов | `scripts/system_check.py --mode load` |

Физическая модель остаётся at least once. При потере агента после загрузки, но до подтверждения, на его диске может остаться неподтверждённый файл. На другом сервере этот ID потребуется повторить. Это не устраняется уникальным индексом БД; централизованное объектное хранилище было бы отдельным расширением. Подтверждённые элементы повторно не загружаются при перевыдаче блока.
